# Skills index — upward management & stakeholder playbooks

Each skill is a **practical playbook**: tactics, phrases/frames, checklists, do/don’t. Not theory essays.

## Operation chain (how the skills fit together)

```text
有計畫 (d) ──► 會議對齊與收 action (c)
     │                    │
     │                    ▼
     │              決策包溝通 (a)  ◄── canonical: BLUF / SOR / 升級話術
     │                    │
     ├────────────────────┼──► 要資源 (b)  ── capacity 數字見 shared/
     │                    │
     │                    └──► 跨隊卡關 (f)  ◄── canonical: influence without authority
     │
     └──► 定期講部門價值 (e)
```

**One-sentence flow:** Plan capacity honestly → run meetings that decide and assign → communicate with options and a dated ask → fund gaps with a business case → unblock partners with influence (not ego) → keep leadership believing your org creates outcomes.

### Apparent “conflicts” that are intentional context splits

| Topic | Not a conflict if you… |
|-------|-------------------------|
| Unplanned **10–15%** vs **20–30%** | Use **A** for quarter commits / roadmap decks; **B** for HC / staffing math ([capacity-model](shared/capacity-model.md)) |
| Pushback in (c) vs (d) | **Room** → (c); **plan/intake doc** → (d); same displace logic |
| Influence in (b) vs (f) | (b) = short tips when you lack budget authority; (f) = full multi-party playbook |
| Escalation in (a) vs (f) | (a) = how sentences/options look; (f) = cross-team packet *content* |
| Playbook vs presentation | Playbook = behavior; presentation = **content** page order for one meeting type (not visual design) |
| Content template vs sample PPTX chrome | Keep BLUF/options/REC/arc; drop navy/margins/fonts when producing real decks |
| Catalog `01`–`09` vs Aurora example story order | Scenario **file numbers** = type index; filled examples follow **calendar/decision arc** **01→02→03→06→04→05→07→09→08** ([storyline-guide](presentations/assets/storyline-guide.md)) — e.g. 08 after 09 is intentional |
| **Never surprise boss** vs **healthy public peer conflict** | **Your manager / skip-level / steering:** never blindside — pre-wire 1:1 first [(a)](executive-communication/decision-ready-updates.md)[(c)](meetings/in-meeting-and-follow-through.md). **Peer / partner teams:** public technical challenge OK when pre-wired and idea-focused [(f)](cross-team/conflict-and-coordination.md). Same “pre-wire” habit; **different target** (boss ≠ peer). |
| **Deck BLUF** vs **Amazon memo** | Everyday / Type 2 → short BLUF deck or one-pager. Type 1 and new-product go/no-go → written narrative (six-pager or PR/FAQ). Same [(a)](executive-communication/decision-ready-updates.md) Options→Rec→Ask; different carrier. Map: [amazon-mapping](shared/amazon-mapping.md). |
| **PR/FAQ** vs **six-pager** | Two artifacts. PR/FAQ = customer-backwards go/no-go **(d)(b)**. Six-pager + study hall = decision meeting **(a)(c)**. Do not collapse into one template. |

## How to use

1. Pick the failure mode this week (e.g. “boss feels we’re reactive”).  
2. Open the matching skill; use **phrases** and **checklists** in the next real meeting/email.  
3. Prefer **canonical** skills above when two files mention the same idea.  
4. Capacity numbers → always [shared/capacity-model.md](shared/capacity-model.md).  
5. Building a **deck for a known scenario** → [presentations/](presentations/README.md)（**內容模板**：結構與話術，不是美工）。  
6. Provenance: [research-notes.md](research-notes.md).
7. Amazon-style memo / PR/FAQ / doors / STO → [shared/amazon-mapping.md](shared/amazon-mapping.md), then the owning a–f skill. Do not add a seventh theme.

## IC vs EM (same spine, different weight)

| Role | Lean on | Watch-out |
|------|---------|-----------|
| **IC / Tech lead** | (a)(c)(d)(f) — influence, written options, planning presence | Don’t over-promise capacity you don’t own; loop your EM |
| **EM / Manager** | All six — especially (b)(e) + contracting with your boss | Own the public commit; pre-wire *your* manager before steering |

## 外商 / 雙語情境（速記）

- **英文決策鏈 + 中文落地**常見：對 global boss 用 BLUF 英文一頁；對本地同仁用 displacing 清單與中文 standup 對齊。  
- **HQ 時差**：預讀 + 書面 decision package 比長會有效；會後 2h summary 更重要。  
- **矩陣式（dotted line）**：RACI 與 pre-wire（f）優先於「誰職級高」。  
- 話術可中英混用；**結構不要混**——永遠 bottom line → options → ask。
