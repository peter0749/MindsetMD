# Amazon mechanisms → existing a–f

**Status:** Provenance + ownership map. Not a seventh theme.  
**Canonical language stays:** BLUF / SOR / GDSB in [(a)](../executive-communication/decision-ready-updates.md); capacity % only in [capacity-model](capacity-model.md).  
**Carriers are parallel:** everyday updates stay short BLUF decks / one-pagers; Type 1 doors and new-product go/no-go use a written memo. Same canonical, different medium.

Do **not** vendor [punt-labs/prfaq](https://github.com/punt-labs/prfaq). It collapses PR/FAQ and the six-pager into one PDF factory and overlays Cagan four-risks + Kahneman + meeting personas — none of that is in the Amazon letters or the author-site concept pages.

## Two Amazon artifacts (keep them apart)

| Artifact | What it is | When | Owns |
|----------|------------|------|------|
| **PR/FAQ** | Future press release (typically &lt;1 page) + FAQ. Start from the customer experience, then work backwards to what to build. | New product / new theme **go/no-go** | **(d)** plan + **(b)** resource case. Internal FAQ *questions* also feed the decision-package list in **(a)(d)(b)** |
| **Six-page narrative + study hall** | Narratively structured memo; meeting starts with silent reading. Harder to write than slides; forces what-matters-first. | Type 1 / high-stakes **decision meeting** | **(a)** decision language + **(c)** meeting shape |

PR/FAQ is a discovery/commit tool. The six-pager is a decision-meeting tool. Do not merge them into one template.

## Internal FAQ — must-answer list (decision package)

Use these as questions the packet must survive. Do not treat them as a slide outline.

**Customer / value**
- Who is the customer, in one specific sentence?
- What is the experience *after* this exists (future PR, not a feature list)?
- What evidence do we have they will care? What is the current workaround?
- What are we explicitly **not** building?

**Plan / feasibility**
- What has to be true for this to work? Which assumption is untested?
- Dependencies and single-threaded owner (name, % time, boundary)?
- What does this displace on the current plan ([capacity-model](capacity-model.md) context **A**)?

**Investment**
- Cost of delay / cost of “no”?
- Alternatives (descope, buy, wait, different owner)?
- How will we know it worked (**input** metrics, not only the output)?

Fill with [(a) SOR](../executive-communication/decision-ready-updates.md). Capacity numbers stay in [capacity-model](capacity-model.md).
